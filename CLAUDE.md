# Git workflow

After making any code change in this repo, always commit and push to `origin main` without waiting for explicit confirmation — this is standing authorization to do so. Each commit message should have a short summary line followed by a body describing what changed and why.

## UI redesign (blank-slate, in progress)
- The plan is `redesign/redesign-plan.md` (from `~/.claude/playbooks/blank-slate-redesign.md`). Design happens in `../wedding-planning-studio`, a separate repo that never sees this codebase. Studio sessions start only with `./start` there.
- Never read from the studio folder, and never send anything from this codebase into it, except `redesign/handoff/` through `redesign/studio.sh enter`.
- Before every `enter`, run the banned-word scan on every file in `redesign/handoff/`.
- Don't save memories that describe the current UI.
- At the start of each redesign session, check the model against the plan's "Picks per step" (or §7.0 in the implementation plan during the rebuild), using the table in `~/.claude/CLAUDE.md`. If the current model is lower, say so and suggest switching.
- When the owner says **"Import the approved design"**: run `redesign/studio.sh import`, confirm `redesign/design/` arrived, tick the step it belongs to (5b, or the matching rows in `needs.md` and §9.1), and offer the next step.
- Rebuild (Step 7): work only on the `redesign` branch (or, when running parallel terminals, a lane branch that merges back into it; see below), one task per session, reading only that task's plan section, design-guide section and prototype file. Never copy markup, CSS, names or wording from the old UI.
- Vercel doesn't build the `redesign` branch (`vercel.json`: `git.deploymentEnabled.redesign` is `false`), so pushes to it make no preview and don't use up the daily deployment limit. Wherever the plans say to check something on a Vercel preview, use a local one instead: `npm run dev`, or `npm run build && npm start` for the production build (on a phone on the same Wi-Fi, `http://<Mac's address>:3000`, from `ipconfig getifaddr en0`). Only `main` deploys.
- After every rebuild task: tick its **Done** box in the implementation plan's §7.0 table, and nowhere else (date, lane and commit; the real `/cost` only if you have it). The phase review ticks §5, §6 and §10 after checking them, and the phase in `redesign/redesign-plan.md`. Add a one-to-three-line entry to `CHANGELOG.md` (details go in the commit body). If a §7.0 model pick changes, change that task's line in `redesign/terminal-split.md` too.
- Checks per task are the light ones in step 5 of the plan's task routine: `tsc`, lint on changed files, related unit tests, the task's own e2e specs and the specs of any shared part it changed while building; `npm test`, the style and old-names checks and `npm run build` once before delivering; `npm run test:emulator` only when the data layer, collections, rules or server code changed. The full e2e suite runs at phase reviews. Don't rerun a check when nothing it covers has changed.
- Design gaps: add them to §9.1 of the implementation plan, then write them as needs in `redesign/handoff/needs.md` (the design-gap loop). Never fill a gap from the old app.
- Parallel terminals (`redesign/terminal-split.md`): **two lanes at most** on this 8 GB Mac (four filled the swap and slowed everything). The main folder stays on `redesign` and is only for merging; tasks are built in the worktrees `../wedding-planning-lanes/t1` and `t2` on branches `lane/t1` and `lane/t2`. Keep every worktree inside `../wedding-planning-lanes/`: the studio's settings block that folder (and Kilo's `~/.local/share/kilo` worktree pool), and a copy anywhere else would be readable from the studio. In a lane, commit locally (don't push lane branches). When a task is done: `git merge redesign` into the lane, fix any bookkeeping conflicts (change log, §7.0 ticks), run the after-merge checks, then `git -C ../../wedding-planning merge --ff-only lane/tN` and `git -C ../../wedding-planning push origin redesign`. If the fast-forward fails, another lane merged first: merge `redesign` again and retry. One merge at a time. Each worktree's tests use its own ports (`.test-port-offset`: 10, 20). Run e2e only with `npm run test:e2e`: it lets one copy run e2e at a time, and given only demo or only emulator spec paths it starts only those servers.
