# Capability inventory

What this wedding planner lets a couple do, written as user needs. It says nothing about how anything looks or where anything sits.

Version 1 (2026-10-14). IDs are stable: new stories get new IDs, removed stories keep their ID marked *dropped*.

Money is always Indonesian rupiah, shown without decimals. Dates are local to the couple.

---

## O. Stay on course

- **O1** When I open the planner, I want to see how many days remain until the wedding and roughly how far through the preparation year we are, so that I feel the pace without working it out.
- **O2** When I open the planner, I want to see the next few things coming up (appointments, vendor calls, payments due, tasks due), so that nothing catches me by surprise.
- **O3** When I want a quick pulse check, I want to see in one place how much we've paid against what we've committed to, how many tasks are done out of how many, and how many guests are coming, so that I know where we stand without digging.
- **O4** When I want to dig into any one of those, I want to get from the summary to the detail in one step, so that the summary is a starting point, not a dead end.
- **O5** When the wedding date is set or changes, I want to record it once, so that every countdown and date-based calculation uses it.

## F. Find and compare suppliers

### Venues
- **F1** When I hear about a venue, I want to capture its name, location, estimated cost, maximum guest capacity and free-form notes, so that I can compare venues later.
- **F2** When I visit or research a venue, I want to attach several photos and see one representative photo for each venue, then look through all its photos at full size, so that I remember what each place looks like.
- **F3** When a venue moves forward or drops out, I want to record its stage (just noted, contacted, visited, booked, ruled out), so that I know where each one stands.
- **F4** When comparing venues, I want to narrow them by name or notes, by stage, by a maximum cost and by a minimum guest capacity, and hide the ruled-out ones, so that I only weigh realistic options.
- **F5** When comparing venues, I want to order them by cost or by capacity, so that the best fit is easy to spot.

### Vendors
- **F6** When I hear about a vendor, I want to capture their name, vendor category, contact person, phone number and notes, so that I can follow up.
- **F7** When I want to reach a vendor, I want to start a WhatsApp chat with them in one step from their phone number, so that I don't retype numbers.
- **F8** When a vendor gives me prices, I want to record several price options (what's included and how much) and mark the one we're leaning towards, so that I can compare offers and know which price counts.
- **F9** When judging a vendor's reputation, I want to record their public review rating and how many people reviewed them, so that I can compare reputation fairly.
- **F10** When a vendor moves forward or drops out, I want to record their stage (just noted, inquiring, considering, chosen, done, ruled out), with ruled-out vendors clearly set apart, so that I know who's still in play.
- **F11** When a vendor stands out, I want to flag them as a favourite and see only my favourites, so that I can get back to them fast.
- **F12** When browsing vendors, I want to move between vendor categories (seeing how many vendors each has), search by name, notes or contact person, and order by name, category, stage, rating or number of reviewers, so that I can find and rank vendors quickly.
- **F13** When a vendor sends a quote, contract or brochure, I want to attach files to that vendor and open them later, so that everything about them is in one place.
- **F14** When our needs don't fit the standard vendor categories, I want to add our own categories that my partner sees too, so that every vendor has a sensible home. Categories have unique names (up to 40 characters), and "other" always comes last.
- **F15** When I want to work on vendor data elsewhere, I want to export the vendors I'm currently looking at to a spreadsheet file, so that I can share or analyse them.

### Shortlist
- **F16** When I narrow a category down to finalists, I want to copy a vendor into a shortlist that brings across their chosen price, their other price options, contact, reviews, next action, notes and files, so that I can compare finalists in detail without changing the vendor's own record.
- **F17** When a finalist offers several packages, I want to record each package with its own price, what's included, review counts, next action, notes and files, and show or hide a finalist's packages as I need, so that I can compare offers within and across finalists.
- **F18** When comparing finalists, I want to record their review count and Instagram follower count, so that I can weigh popularity.
- **F19** When comparing finalists, I want to see finalists by vendor category (with counts) and order them by category, so that I compare like with like.
- **F20** When a vendor gets new files, I want the matching finalist to pick them up automatically, so that I never chase documents in two places.
- **F21** When I add a finalist from scratch, I want to do it without first creating a vendor, so that quick comparisons stay quick.

## B. Book and pay

- **B1** When I choose a vendor or book a venue, I want it to become a confirmed booking automatically, so that I never enter it twice.
- **B2** When I've booked something that never went through comparison, I want to add a confirmed booking directly, so that every commitment is tracked.
- **B3** For each confirmed booking, I want to record its name, booking category, total price, amount actually paid so far, who is paying (the funder), the next target date, the next action and attached contracts or receipts, so that each commitment is fully documented.
- **B4** When a booking is paid in instalments or has add-ons, I want to split it into parts, each with its own name, price, amount paid, funder, target date, next action and files, with the booking's totals worked out from its parts, so that staged payments add up correctly.
- **B5** When reviewing money, I want to see the total committed, the real amount paid and what remains to pay, with overspending clearly flagged, so that I know our true position.
- **B6** When payments are coming due, I want to see every unpaid amount that has a target date, sorted by date and marked overdue, due today, due within 7 days or later, with how much remains and who pays, so that we never miss a payment.
- **B7** When we split costs between funders (a fixed set of four people or families, plus "not yet assigned"), I want to see for each funder how much they've paid and how much they still have to pay, and how much paid spending has no funder yet, so that everyone knows their share.
- **B8** When weighing an option we haven't committed to, I want to record what-if items (also splittable into parts) with their own totals kept apart from real bookings, plus a projected total of real and what-if combined, so that I can see the effect before deciding.
- **B9** When reviewing bookings or what-if items, I want to order them by any field, with a booking's parts always staying with their booking, so that I can scan by price, date or funder.

## G. Guests

- **G1** When building the guest roster, I want to record each guest's name, how they're connected to us (free text, for example "groom's uncle" or "bride's colleague"), country, RSVP (waiting, attending, not attending), which event they're invited to, whether the invitation has been sent, how many plus-ones they bring and any food notes, so that I have everything needed for invites and catering.
- **G2** When inviting, I want to choose from these event options for each guest: both events, the ceremony only, the reception only, "reception if space allows" and "unsure, living abroad", so that I can plan two differently sized events.
- **G3** When working out numbers, I want to see the total headcount including plus-ones, how many guests are attending, the attending headcount including plus-ones, and headcounts for both events, the reception and the ceremony, so that I can brief venues and caterers.
- **G4** When looking at guests invited to both events, I want to see headcounts for the groom's family, the bride's family and the groom's business connections, worked out from how each guest is connected, so that I can balance the two sides.
- **G5** When looking for guests, I want to search by name, connection, country or food notes, narrow by RSVP and by event, and order by any field, so that I can answer questions like "who hasn't replied?".
- **G6** When I add guests, I want each one to keep a stable number based on when they were added, so that we can refer to guests unambiguously.
- **G7** When I remove a guest, I want to confirm first (being reminded of their plus-ones) and be able to undo for a few seconds, so that a slip doesn't lose anyone.
- **G8** When I'm out with only my phone, I want to read and edit the guest roster comfortably, so that I can update RSVPs as they come in.

## T. Track every piece

One running record of every wedding item and who provides it, separate from vendor comparison.

- **T1** When I think of something the wedding needs (for example "reception venue", "bride's mother's makeup"), I want to record the item and its vendor, or note that the vendor is still unknown, so that nothing is forgotten.
- **T2** For each item, I want to mark whether it's confirmed, which events it's for (any of reception, holy matrimony, sangjit, pre-wedding) and who it's for (general, groom, bride, or a specific family member: groom's father, mother, brother or sister, bride's father, mother or brothers), so that I can see the picture per event and per person.
- **T3** When some items need attention soon, I want to mark them as "work on next" and have them stand out, so that I know where to focus.
- **T4** When reviewing, I want to see how many items there are, how many are confirmed and how many are marked "work on next", so that I can gauge progress.
- **T5** When looking for items, I want to search item and vendor names and narrow by confirmed, event, person and "work on next" (several events or people at once), see how many of the total match, and clear everything in one step, so that I can focus on one slice.
- **T6** When reviewing, I want to order by any field and return to my own order, so that I can sort temporarily without losing my arrangement.
- **T7** When organising, I want to arrange items in my own order, and insert one or several new items directly after any item, or many (1 to 50) at the end, so that related items sit together.
- **T8** When I remove an item, I want to confirm first and be able to undo for a few seconds, putting it back exactly where it was, so that a slip doesn't lose work.
- **T9** When a change fails to save, I want to keep what I typed and retry, so that I don't retype it.
- **T10** When the tracker is used for the first time, I want it to start with our known items already filled in, so that we don't enter them by hand.

## S. Stay on schedule

- **S1** When I arrange something, I want to record it with a title, kind (vendor or organiser call, appointment, payment, deadline, other), all-day or a start time, an optional end time, a related venue or vendor, a location or call link, and notes, so that I know when and where.
- **S2** When something happens or is called off, I want to mark it completed, cancelled or back to scheduled, edit it, or delete it after confirming, so that the schedule stays truthful.
- **S3** When I look ahead, I want one combined agenda of my own events, payments due from bookings and tasks with due dates, grouped as overdue, today, tomorrow, next 7 days and later, with completed and cancelled items available on demand, so that I see everything time-bound in one place.
- **S4** When I want the bigger picture, I want a month-at-a-glance calendar, to step back and forward by day or month, and to jump back to today, so that I can spot busy weeks.
- **S5** When looking for something, I want to search the schedule and narrow it to one kind (payments, tasks, calls, appointments, deadlines, my own events, other), so that I find it fast.
- **S6** When glancing at the schedule, I want counts of overdue, today and next-7-days items, so that I know how urgent things are.
- **S7** When an agenda item comes from a booking or a task, I want to jump to where that booking or task lives, so that I can act on it.
- **S8** When I need to do something, I want to record a task with a title, due date, notes and smaller steps (each with its own due date and done state), and see how many steps are done, so that big jobs become manageable.
- **S9** When working through tasks, I want open tasks ordered by due date (undated last), finished tasks kept apart but recoverable, and to delete tasks, so that I focus on what remains.

## R. Keep records

### Documents
- **R1** When I write plans or research, I want rich documents: title levels, a choice of fonts and sizes, bold, italic, underline, strikethrough, bullet points and numbered steps, text and highlight colours, quotes, code, links, undo and redo, and clear formatting, so that notes are readable and structured.
- **R2** When I lay out numbers or comparisons, I want tables in documents: choose a starting size, add and remove entries in both directions, add many entries at once (1 to 50), turn a title line on or off, adjust widths and remove the table, so that I can build small spreadsheets inside notes.
- **R3** When reading a table, I want to sort it by one field, ascending or descending, numerically when the values are numbers, with blanks last, so that I can rank options.
- **R4** When a table holds amounts, I want running totals using a SUM formula over cells or ranges (spreadsheet-style references), including ranges that grow automatically as entries are added, with clear errors for bad references or circular totals, so that totals stay correct as I edit.
- **R5** When I edit a document, I want it saved automatically and to always know whether it's saved, saving, unsaved or failed (with a way to retry), so that I never lose writing.
- **R6** When I come back to my documents, I want them ordered by most recently edited, each with a short preview, searchable by title or content, and I want to create new ones, so that I find the document I need quickly.
- **R7** When a document is no longer needed, I want to delete it after a clear warning that this can't be undone, so that I don't delete by accident.

### Files
- **R8** When storing wedding paperwork, I want nested folders, to move between them easily and always know where I am, and to create, rename and delete (empty) folders, so that files stay organised.
- **R9** When I have documents, I want to upload one or several at once (PDF, Word, Excel, CSV, ZIP, text, images) up to 10 MB each, with oversized PDFs shrunk automatically and progress shown while uploading, so that the free storage limits don't block me.
- **R10** When I upload a file, I want to give it a name, an optional category (with wedding suggestions or my own) and a description, so that I can tell files apart later.
- **R11** When I need a file, I want to open or download it, see its size and date, move it to another folder, edit its details and delete it after confirming, so that the archive stays tidy.

## A. Access and work anywhere

- **A1** When I open the planner, I want to sign in with Google or with email and password, so that only my partner and I can see our plans. Only our two accounts may read or change anything.
- **A2** When my partner changes something, I want to see it straight away without refreshing, so that we work from the same information.
- **A3** When I am out and about, I want to install the planner on my phone and open it like an app, so that it's always one tap away.
- **A4** When switching between phone and computer, I want every job to work well on both, so that I can plan wherever I am.
- **A5** When I'm signed in, I want to see which account I'm using, reach the wedding settings and sign out, so that I stay in control of access.
- **A6** When I edit any detail, I want it saved immediately without a separate save step, so that editing is quick.

## States the design must cover

- **Nothing yet:** every kind of record can be empty (no venues, vendors, finalists, bookings, payments due, what-if items, guests, tracker items, events, tasks, documents, folders, files, photos or price options).
- **No results:** a search or narrowing that matches nothing.
- **Loading:** data arriving after sign-in or when switching areas.
- **Failure:** data couldn't load, a change couldn't be saved (keep my input and offer a retry), an upload failed or was too large.
- **Signing in:** in progress, wrong credentials, account not allowed.
- **Not connected:** the backend isn't set up yet (a demonstration mode with no data and saving disabled).
- **Offline:** previously visited areas open without a connection but show no data.
- **Live-synced:** a partner's change arrives while I'm looking.
- **Saving:** document autosave states (unsaved, saving, saved, failed).
- **Uploading:** progress per file, and compressing a large PDF.
- **Confirming:** before destructive actions, and a short undo window after removing guests or tracker items.
- **Overdue / due soon:** payments, events and tasks past or near their date.
- **Overspent:** paid more than the price, so remaining is negative.
- **Busy:** an action in progress (adding, removing, restoring).

## Roles and permissions

- Two people, the couple. Both have identical full access to everything.
- No read-only role, no guest access and no shared links today.
- Anyone else who signs in can't read or change any data.

## Hard constraints

- Works on phones and desktops; installable on phones.
- Live sync between both partners' devices.
- Files: 10 MB per file; larger PDFs are compressed before upload.
- Rich-text documents with tables and SUM formulas.
- Export of vendors to a spreadsheet file (CSV).
- Currency in Indonesian rupiah; a single interface language (see the brief).
- Long free-text notes (hundreds of characters) on venues, vendors and finalists, with web links that open.
